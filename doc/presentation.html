Document Search Platform

Agentic RAG backend for OpenWebUI — Docling, pgvector, LlamaIndex, CrewAI, Ollama, Phoenix, RAGAs.

Local-first. Python + uv. REST + OpenAI-compatible chat.

What we were asked to build

  • Ingest provided PDFs into a knowledge base
  • Full preprocessing → split → vectorize → index path
  • Contextual agentic RAG retrieval
  • Trace every inference call
  • Prompts outside application code
  • Measure accuracy and performance
  • REST APIs for an OpenWebUI frontend
  • Architecture, deck, OpenAPI, README

Ingestion

  • PDFs in data/pdfs (sample AetherCorp corpus ships with the repo)
  • Docling structure-aware chunks, not naive page splits
  • Optional contextual prefixes from prompts/contextualize.yaml
  • 768-d embeddings into pgvector with hybrid keyword search
  • Catalog table ingested_documents for status in the API

Contextual agentic RAG

  1. Planner — rewrite follow-ups using chat history
  2. Retriever — 1–3 queries, LlamaIndex hybrid search
  3. Synthesizer — answer only from context, cite files
  4. Critic — JSON faithfulness; one revision loop

Prompts are YAML. Edit prompts/ without touching Python. Phoenix records each LLM span.

Accuracy and performance

  • Golden set: 8 questions grounded in the sample PDFs
  • Metrics: RAGAs faithfulness, relevancy, context precision/recall
  • Always-on: lexical hit-rate, average and p95 latency
  • Health: Postgres, Ollama, Phoenix independently reported

Local demo path

  1. uv sync --all-extras and docker compose up -d
  2. ollama pull llama3.2 nomic-embed-text
  3. uv run python scripts/ingest.py
  4. uv run uvicorn docsearch.main:app --port 8000 --reload
  5. Open http://localhost:3000 — model docsearch-agentic
  6. Ask: “How many PTO days do full-time AetherCorp employees receive?”
